PHASE 3.5 POST-IMPLEMENTATION FIXES (Round 1)

This is a categorized, prioritized list of fixes from on-device UAT testing. Work through them in the order listed. Standing rules apply: token discipline (no hardcoded colors), no em dashes or hyphens in user facing text.

=== CATEGORY A: BUGS (fix first) ===

## A1. Brain dump items not appearing
BUG: items added via "just a thought" are not showing up in the brain dump space. Investigate why brain dump items are not persisting or rendering. This is a data/routing bug, not a UX issue. Fix the underlying save/query path first before addressing the UX changes below.

## A2. Move button not working
BUG: tapping Move inside a task drawer, changing from "today" to "tomorrow", nothing updates. The task stays in its original priority. Investigate the move handler in the task detail sheet. For UNDATED tasks, this should work as a direct priority change. For DATED tasks, this should show the redirect prompt (change date / snooze / pin / remove date) per our Phase 3.5 design. Neither is working. Fix both paths.

## A3. Pin button missing
BUG: there is no visible way to pin a task from the task drawer. The pinning UI was spec'd in Phase 3.5 (a pin icon/button near the top of the task drawer, three-state cycle for recurring tasks). Implement it: a pin icon near the top of the task detail drawer. Tapping it pins the task (adds it to the Pinned section at the top of the board). The icon should visually change state (unpinned / pinned / persistently pinned for recurring tasks). See the Phase 3.5 spec for full pinning behavior.

## A4. Light mode status bar text color
BUG: in light mode, the Android status bar text (time, battery, signal) is white on a light background, making it unreadable. Dark mode is fine (white text on dark). Fix by setting the status bar appearance to use dark icons/text when the app is in light mode. Use the WindowInsetsControllerCompat or the equivalent Compose API to set isAppearanceLightStatusBars = true when in light mode.

## A5. Bottom tab buttons cut off by navigation bar
BUG: the board and brain dump tab buttons at the bottom of the screen are obscured by the system navigation bar (gesture bar or button bar). Fix by properly handling system window insets. The bottom navigation must sit ABOVE the system navigation bar, not behind it. Use Modifier.navigationBarsPadding() or WindowInsets.navigationBars in the Scaffold.

## A6. Snackbar/notification banner never dismisses
BUG: the "syncing with Notion" banner and the "Task moved" / undo snackbar persist indefinitely and block the add-task button. These must auto-dismiss after a reasonable duration (3 to 5 seconds) AND be manually dismissible (swipe to dismiss, both sideways and downward). The undo action must remain tappable during the visible window but the snackbar itself must not persist forever.

=== CATEGORY B: UX IMPROVEMENTS (do after bugs) ===

## B1. Brain dump entry: elevate to a top-level toggle
Currently brain dump is buried as "just a thought" under the "When" options. CHANGE: add a task-type toggle directly below the title field ("What needs doing?"). Two options: "Task" (default when on the board view) and "Brain dump" (default when on the brain dump view). This replaces the "just a thought" option under When. Remove the "just a thought" pill from the When section. Remove the "use just a thought when adding a task" instructional text from the brain dump screen.

When "Brain dump" is selected, the When options (date picker, rough range) should still be available but optional. A brain dump item with a date becomes a review-date reminder (see Phase 3.5 spec), not a priority-placing due date.

## B2. Notification system redesign: top notification bar
Replace the bottom snackbar pattern with a TOP notification bar that slides in below the Sift header (below the title and the view-mode/refresh/settings icons). This bar:
- Slides in from the top with a subtle animation
- Has a visually distinct background color (use a token, not hardcoded) that differentiates it from the board
- Is minimal: one line of text plus optional action button(s) (like Undo)
- Auto-dismisses after 3 to 5 seconds
- Can be manually dismissed with a swipe (horizontal or upward)
- Replaces itself when a new notification arrives (never stacks)
- Uses a single, reusable notification bar composable that all notification-type messages route through (task added, task moved, sync status, errors). This composable is the single source of truth for notification styling, so we update one component and all notifications match.

Notification types to route through this bar:
- Task added ("Added to Soon")
- Task moved ("Task moved" + Undo)
- Task completed ("Task completed" + Undo)
- Task removed ("Task archived" + Undo)
- Sync status ("Syncing..." then "Synced" or "Sync failed: [reason]" + Retry)
- Errors ("Cannot connect to Notion. Check your connection." + Retry or Reconnect)

## B3. Add-task drawer: reduce size and improve layout
The drawer is too large. Reduce its height by approximately 30 percent. Specific changes:

1. The drawer should have TWO states: minimized and expanded.
   - MINIMIZED (default after adding a task): shows only the title field ("What needs doing?") and the task/brain-dump toggle. The title field should be in the same vertical position as the "Add task to board" button is in the expanded state, so tapping into it feels like tapping the same spot. The top notification bar shows "Added to [priority]" with a Change option.
   - EXPANDED (when the user taps into the title field or opens the drawer): shows the full add-task form (title, task/brain-dump toggle, bucket pills, when options, and the collapsed more-options area).

2. The "Add a task" confirmation button text should read "Add task to board" (to distinguish from the drawer header which also says "Add a task").

3. When the user hits the back button or swipes the drawer down, SAVE THE DRAFT STATE in memory (title text, selected bucket, selected date, etc). When the drawer is reopened, restore this draft. This is in-memory only, not persisted. When the app is fully closed, the draft is cleared.

4. The "More options" tap target should be REPLACED with a swipe-up gesture on the drawer itself. The drawer handle area (the drag indicator at the top of the sheet) and a subtle visual cue (a small upward chevron or "swipe up for more") should indicate that swiping up reveals additional options. The additional options area contains:
   - Notes field (placeholder text: "Add some context (notes)")
   - Recurrence picker (see B5 below, lives next to the date/time area as an icon)
   - Protected flag toggle
   - Labels selector

## B4. Date and time display improvements
1. The "When" section should be simplified: replace the current sub-header and pill buttons with a single calendar icon that indicates "pick a date (optional)". No sub-header text needed.
2. Once a date is selected, display it in a human readable format: "July 8th, 2026" not "2026-07-08". Respect locale for month names.
3. Once a date is selected, show a clock icon next to it. Tapping the clock adds a time. Display the time as "6:00 AM" or "8:24 PM" (12-hour format by default). If the user has selected 24-hour time in Settings > Display, show "18:00" or "20:24" instead.
4. The date-bucket preview ("-> Soon") should appear ONLY inside the date picker while the user is actively selecting a date (so they can see which priority band the date falls into). Once the date is confirmed and the picker closes, do NOT display the bucket name next to the date in the add-task form. The top notification bar handles that information when the task is saved. This resolves a conflict with a previous design decision: the priority preview is still there to build trust during selection, but it does not clutter the form after selection.
5. When a date IS selected, the "How soon?" rough-range pills (Soon-ish / Later / Whenever) must smoothly COLLAPSE AWAY (not gray out) with a ~200ms animation. In their place, show a small muted helper line: "Sift handles the priority. Adjust anytime." If the user REMOVES the date (taps clear/X on the date), the rough-range pills smoothly expand back into place. This is a reversible, living interaction. Graying out leaves useless visual clutter; collapsing cleans the screen and creates a natural moment for the confirmation text.

## B5. Recurrence picker redesign
The recurrence options should live next to the date/time area as an icon (a circular arrow or repeat icon). Tapping it opens a simple recurrence picker. Design based on the Things app pattern (proven, clean):

1. At the top, show a plain-English sentence summarizing the current rule: "Every 2 weeks on Tuesday and Thursday" (generated from the RRULE).
2. Below, show the controls that build the sentence:
   - Frequency: Daily / Weekly / Monthly / Yearly (horizontal selector or dropdown)
   - Interval: "Every [N]" with a number picker (1, 2, 3...)
   - For Weekly: a row of tappable day-of-week buttons (M T W T F S S), multiple selectable
   - For Monthly: option to repeat on a specific day of the month or a relative day (first Monday, last Friday)
3. Keep it compact. This is not a full-screen view; it is a sub-sheet or an expanded section within the drawer.
4. The resulting RRULE is generated from the selections and stored per the existing recurrence spec (technical RRULE field plus plain-English display field).

## B6. Swipe action improvements
1. When swiping a task on the board, a background color should reveal behind the task row indicating which action is being performed (green tint for complete, a muted/neutral tint for snooze).
2. As the user swipes further, reveal text alongside the icon: "Complete" (swipe right) and "Snooze" (swipe left).
3. BACKLOG (not this batch): customizable swipe direction assignments in settings. For now, ship with right = complete, left = snooze as the fixed default. ADD a "coming soon" placeholder row in Settings under a "Gestures" or "Swipe actions" section that reads "Customize swipe actions" with a "Coming soon" badge. This gives it a visible home without building the feature.

## B7. Task detail drawer improvements
1. The drawer should be minimal by default and expandable by swiping up (same pattern as the add-task drawer). Default view shows: task title, bucket (with color), priority context, pin button, and a prominent complete button.
   - Priority context labeling rules: for DATED tasks, show "Due today" or "Due July 8th" (the word "due" plus the date). For UNDATED tasks (placed by rough range), show JUST the priority name: "Today" or "Soon" or "Later" (no preposition, no "due", no "in"). The word "due" ONLY appears when there is an actual due date. This makes the distinction between hard deadlines and rough priorities instantly clear without any additional configuration.
2. The complete button should be a standalone, visually prominent button (filled, accent colored) that is easy to tap and hard to accidentally hit other things. Do NOT combine complete and delete into a single swipeable element in the drawer (that risks confusion with the board-level swipe gestures).
3. The edit, move, and remove actions should be secondary: smaller icon buttons or a three-dot menu. "Move" should be relabeled to "Change priority" for undated tasks or "Change date" for dated tasks (more specific than the ambiguous "Move").
4. On misclick of complete, the undo notification should appear in the top bar AND reopen the task drawer if the undo is tapped (so the user lands back where they were).
5. Swiping up on the task detail drawer reveals: full notes content, labels, recurrence info, protected status, and a "Via: Notion" or "Via: Sift" provenance line (shown only in the expanded view, not the default). The provenance should indicate whether the task was created in Sift or synced from Notion. Track this by storing a "created_by" field in local Room storage ("sift" or "notion") when the task is first seen.

## B8. Tab icons: make board and brain dump visually distinct
The bottom tab icons for board and brain dump currently use the same icon. Change the brain dump tab icon to a brain icon (or a lightbulb, or a cloud, whatever best conveys "ideas/thoughts" and is available in the Material Symbols set). The board tab icon should be a grid or list icon that conveys "tasks."

## B9. Notion link icon
The "open in Notion" icon in the task detail should be visually distinct from the other icons. Do NOT use the Notion logo (trademark risk for a third-party app without explicit permission). Instead, use a clearly different icon that conveys "open externally": an arrow pointing out of a box (the standard "external link" icon), labeled with tooltip text "View in Notion". Make sure this icon is NOT the same as any other icon used in the app (board view, brain dump, settings).

## B10. Refresh button and sync status redesign
1. Remove the static "Updated: 7:00 AM" pill.
2. The refresh icon should animate (spin) while syncing is in progress.
3. On success: the icon returns to static AND a small, succinct time-ago label appears next to or below it: "6m ago", "1h ago", "2h ago", "1d ago". Keep this very compact.
4. On failure: the top notification bar shows the error with a Retry button ("Cannot connect to Notion" / "No internet connection" / etc). The refresh icon itself should show a subtle error state (a small red dot or badge).

## B11. Brain dump visual consistency with the board
The brain dump screen should feel like an extension of the board, not a separate app. Specifically:
1. The Sift header, view-mode icons, refresh button, and settings icon should remain visible in the brain dump view (same top bar as the board).
2. The brain dump area replaces the priority grid content area but keeps the same shell/chrome.
3. BACKLOG (not this batch): personalized header ("BJ's tasks" / "BJ's brain dump" with a name collected during onboarding). For now, keep "Sift" in the header for both views.
4. BACKLOG (not this batch): brain dump categories/tags for organization. The existing labels system could serve this purpose. For now, the brain dump is a flat list.
